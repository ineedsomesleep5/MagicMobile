## What changed and why

### 1. One palette instead of two

`ContentView.swift` held `MagicPalette`, a second palette with **a different gold**
(`0.82/0.62/0.27`) from `GameBoardTheme`'s (`0.84/0.65/0.25`). That is why the menu and
board never quite matched. `MagicPalette` now forwards every member to
`GameBoardTheme`; `GameBoardTheme` gained `mossMid`, `parchmentShadow`, `borderIron`,
the three tones that existed only in the duplicate.

This was done as a forwarding layer rather than a rename across all **404** call sites,
to keep the diff reviewable. New code should use `GameBoardTheme.current` directly.

Deck Studio stays light on purpose — it is the "workshop" mode, and deckbuilding is long
reading over dense lists — but now takes geometry from `GameBoardDesignTokens` via the
new `DeckStudioMetrics`. See the new "Two modes, one spine" section in `DESIGN.md`.

### 2. The app mark is used in the app for the first time

`AppIcon-1024.png` is 8-bit RGB with **no alpha**, flattened onto near-black, and the
black mana circle `(2,1,2)` is *darker* than its own backdrop `(12,12,14)` — so a
luminance key eats the circle. The cut-out was produced by a two-pass corner flood fill
with fixed reference colours, which leaves the enclosed circle intact, then a 3×3
coverage feather. Result: `Assets.xcassets/mage-mobile-logo.imageset` (709×646 RGBA).

If the logo art is ever re-exported **with** an alpha channel, replace that asset and
delete this workaround; it is a salvage, not a preference.

Menu mana pips now use the shipped `mana-w/u/b/r/g` assets. They were SF Symbols for
weather (`sun.max.fill`, `drop.fill`, …).

### 3. Board backgrounds

- `commander-stone-arena.png` is 1672×941 landscape-only. Aspect-filled on a 1290×2796
  screen it kept **26% of its width**, cropping the brass frame and crystals entirely.
  Added `commander-stone-arena-portrait.imageset`, generated by a three-slice vertical
  stretch that holds the top/bottom frame bands at natural scale and stretches only the
  flat stone. A mirror-tiled variant was tried first and rejected — it visibly repeated
  the side medallions. Real portrait art would still be better than this.
- `BattlefieldSurface.portraitModeEnabled` was **declared and never read**, so the board
  decided orientation from raw geometry and ignored the auto-rotate preference the menu
  honours. Now routed through `GameOrientationMode.isPortraitLayout`.
- The menu background is now selectable (`MenuAppearancePicker`,
  `magicmobile.menuAppearance`) like the battlefield already was.
- Appearance swatches were unevenly sized because a resizable image reports a large ideal
  width and wins the `HStack`'s space. Fixed by letting an empty `Color.clear` own the
  size and drawing the art in an `.overlay`.

**Trap:** `BattlefieldSurface` is reused as a generic page background in **12 non-board
screens** (`OnDeviceRootView.swift:647`, `NativeDeckLibraryView.swift:53/297/441/546/663/691`,
`DeckLibrary.swift:886/960`, `ContentView.swift:4397/11435/11515/12532`). Any further
background change leaks into all of them. Also, `GameManagementMenu` is presented at a
fixed `.presentationDetents([.height(380)])`, so a second picker there would overflow;
that is why the menu picker was added to Settings and the legacy Display panel only.

### 4. Colour identity was `null` on every card

`export_ios_catalogue.py:127` hardcoded `colorIdentity=None`, with a test asserting it
stayed null. Measured: **31,726 / 31,726 cards null**. That single stub caused the
"Identity unknown" deck chip, the Spellbook "commander color identity is unknown"
warning, and a colour filter that could never match (it compared `nil == Set(...)`).

Now derived per CR 903.4: mana-cost symbols ∪ rules-text symbols **excluding reminder
text** (`<i>…</i>`) ∪ basic land types. Verified against 17 hand-checked cards including
Sacred Foundry (land types), Ancestral Vision (colour indicator via `colors`), Command
Tower and Arcane Signet (genuinely colourless identity).

### 5. Role analysis was near-useless; now curated

The old classifier was 11 regexes all anchored with `^` against the **whole** oracle
text. Measured over the 31,384 cards with rules text:

| Role | Old matches | % |
|---|---|---|
| Ramp | 756 | 2.41% |
| Draw | 77 | 0.25% |
| Interaction | 262 | 0.84% |
| Board wipes | 20 | 0.06% |
| **Protection** | **1** | **0.003%** |
| Graveyard | 10 | 0.03% |
| Recursion | 62 | 0.20% |
| Tutors | 5 | 0.02% |

Only 3.8% of the catalogue matched anything. Protection matched exactly one card in the
game. Caleb's report of "0 board wipes, 0 protection" was not a display bug.

**New source of truth:** Scryfall's community-curated oracle tags, fetched at build time
by the new `packages/ondevice-engine/scripts/fetch_role_tags.py` and baked per card into
`ondevice-catalogue.json`. The phone resolves roles **entirely offline**; no per-user
network. Tag data is CC-BY and credited in the analysis panel copy.

Precedence in `DeckStudioRoleClassifier.classify`: user override → curated tag → regex
fallback. The regex fallback was fixed to strip reminder text and match **per clause**
instead of per card, but deliberately still refuses to classify triggered and
conditional effects — `role-checks.swift` has explicit guards for that and they were
kept, not relaxed.

> Note: an earlier assumption that the classifier needed HTML stripping was **wrong**.
> `EngineDisplayText.text()` already strips all markup before the classifier sees it.
> The measurement showing `<br>`/`<i>` damage was taken on raw catalogue JSON, not on
> the runtime input.

### 6. Deck Studio UI

- **Online Scryfall search was vertically centred** — `searchContent` is a `VStack` whose
  online branch has no vertically-expanding child until results arrive, so SwiftUI
  centred the block. Fixed with `.frame(maxHeight: .infinity, alignment: .top)`.
- **Card images** added to online search, combo ingredient rows, role-insight lists and
  the curve drill-down, reusing `DeckStudioArtwork`. Local catalogue thumbnails went
  36×50 → 52×73.
- Combo ingredients moved into a `LazyVStack`; artwork fetches are serialized at
  `requestSpacing = 0.51s` app-wide (~2/s), so a long non-lazy list queued fetches for
  rows nobody was looking at.
- **Artwork was off by default** (`magicmobile.deckArtworkNetworkEnabled = false`) with
  the toggle buried behind a toolbar glyph. That is the likely reason Caleb saw no images
  anywhere. Added `DeckStudioArtworkInvitation`, an inline explained opt-in shown where
  image-bearing lists live. Still opt-in; the privacy text was left as written.

## What is left

### The blocker

`scripts/ios/deploy-testflight.sh` refuses:

```
Native TestFlight guard refused: App and native artifact have different engine inputs:
packages/ondevice-engine/scripts/export_ios_catalogue.py
packages/ondevice-engine/scripts/fetch_role_tags.py
```

The shipped `libmmengine.a` was built at `3f6405a`. `verify_native_candidate.py` requires
every guarded engine input to be byte-identical between that commit and HEAD, and its own
comment says it *"intentionally also rejects changes to other build scripts instead of
guessing whether they matter."*

**Do not add these files to the exemption list, and do not relocate them to dodge the
gate.** The guard is correct here: `export_ios_catalogue.py` reads the engine's build
outputs and pins their SHAs, so if it changes, the app's notion of which cards are
playable can drift from the engine's. That is exactly the risk the gate exists to catch.
The legitimate fix is to re-pair the engine at HEAD.
