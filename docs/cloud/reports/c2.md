# C2: engine release A

Cloud session C2 of the game improvement program (docs/GAME_IMPROVEMENT_PROGRAM.md, Phase 2), for R2
(TestFlight 40 / Android 24). Branch `cloud/c2-engine-a`, draft PR #163. Nothing here was released,
uploaded, signed, applied live or pushed to main, and no native workflow was dispatched.

## What changed

1. **`stackControllers`** (`ViewProjector.java`): every per-seat snapshot gets a top-level object from
   stack object ID (same keys as `gameView.stack` and `stackOrder`) to the controller's engine player
   ID (same IDs as `gameView.players[].playerId` and `enginePlayerId`). It's public, so every seat gets
   the same map; `{}` on an empty stack.
2. **`respondsToStack`** (`StackResponses.java`, `ViewProjector.java`): every
   `gameView.canPlayObjects.objects[id][category][]` row gets a boolean saying whether that play could
   answer what is pending now: the stack, or attacks that haven't dealt combat damage yet. It's built from
   ability, target and effect objects, never rules text. It's conservative: anything the engine can't
   judge counts as a response. Rules are listed in packages/ondevice-engine/docs/PROTOCOL.md. In short:
   - counts: counters and copies, anything that can target a stack object, its source or what it
     targets, abilities of a threatened permanent, sacrifice outlets when something threatens your
     permanents, protection against an untargeted sweeper, combat tricks and flash blockers while
     attacks are pending, and untargeted effects other than draw, mana or land;
   - doesn't count: lands, mana abilities, burn with nothing relevant to hit, cantrips, and
     keyword-only flash creatures outside combat;
   - every row is `false` with an empty stack and no attack.
3. **AI difficulty** (`AIDifficulty.java`, `MobileAICancellation.java`, `XmageEngine.java`; mobile
   wrapper only, no upstream edits):

   | Skill | Upstream search depth | Mistake chance |
   |---|---|---|
   | 1 | 2 (was 4) | 15% |
   | 2 | 3 (was 4) | 10% |
   | 3 | 4 (unchanged) | 5% |
   | 4–10 | `max(4, skill)` (unchanged) | 0% |

   - **Depth.** "N plies" means N actions seen resolved, which is upstream depth N+1. Measured on real
     boards: at depth 1 the AI scores a spell while it's still on the stack and never casts anything,
     so a literal depth 1 would be a broken opponent. Depth 2 casts the obvious creature and bolts the
     obvious target.
   - **Play mistakes.** After a fresh priority search that chose to act, the AI takes the best other
     play its search scored that is no worse than doing nothing, or else passes and searches again at
     its next priority. Seen in the tests: Bolt to the face instead of killing the Grizzly Bears.
   - **Combat mistakes.** It may hold back every attacker, but never when its attack could be lethal.
     It may skip blocks, but only while the attack costs under half its life.
   - **Rolls.** One SplitMix64 generator per seat, saved with checkpoints. Think time is unchanged
     (`skill × 3` s).
   - **Calibration overrides for C3.** AI seats accept optional `aiSearchDepth` (1–10),
     `aiMistakePercent` (0–100) and `aiSeed` (64-bit). A seed makes the mistake rolls repeatable;
     XMage's shuffles and tie-breaks stay unseeded. The defaults live in one place,
     `AIDifficulty.searchDepth` and `AIDifficulty.mistakePercent`.
4. **Relocations research**: docs/cloud/c2-relocations.md.
   - No GraalVM 22.1 option removes the ~4.5 M relocations. They are vtable code pointers;
     `-H:+RelativeCodePointers` arrives in GraalVM 25.
   - RELR packing would need minSdk 28 or 30 and would still apply every relocation.
   - The doc proposes a measurement-only change to `scripts/android/build_native.sh` (a
     `reloc-report.txt` after linking, plus a corrected RELR comment), with the expected effect and the
     M1–M4 measurement steps. `build_native.sh` itself is not edited.

Docs: packages/ondevice-engine/docs/PROTOCOL.md (both snapshot fields, AI seat settings), docs/RANKED.md
("Why this curve"), docs/LESSONS.md (two new entries, one corrected).

## What the apps must adopt (Mac session)

All fields are additive. Both snapshot adapters read fields by name and ignore unknown keys, so an
un-updated app keeps working.

1. **`stackControllers`** (top-level in each per-seat snapshot, beside `stackOrder`):
   `{ "<stackObjectId>": "<enginePlayerId>" }`. Fill each stack item's `controllerId` from it
   (iOS `OnDeviceSnapshotAdapter.swift`, Android `game/OnDeviceSnapshotAdapter.kt`). When absent (older
   engine), keep today's inference. This feeds the "Stop for my own spells" smart-pass setting: when it
   is off, pass while the top stack object's controller equals `enginePlayerId`.
2. **`respondsToStack`** (boolean on every row of `gameView.canPlayObjects.objects[id][category][]`,
   beside `manaAbility` and `spellAbility`; only the priority seat gets the rows). In smart pass (iOS
   `OnDeviceYieldPolicy.swift`, Android `game/OnDeviceSmartPass.kt`, where `passPrompt` now returns
   `null` whenever the stack is non-empty and there's any play): with a non-empty stack, or during declare
   attackers, declare blockers or first-strike damage with attackers declared, stop only if some non-mana
   row has `respondsToStack != false`. A missing field counts as `true`, which is today's behaviour.
   Add parity cases for both platforms.
3. **AI**: no protocol change for the apps. Keep sending only `aiSkill`. Don't send `aiSearchDepth`,
   `aiMistakePercent` or `aiSeed`; they're for calibration. The tier table in docs/RANKED.md is
   unchanged, but Bronze through Gold play differently. Update player-facing skill text if any of it
   claims skills 1–4 play alike.
4. **Checkpoints**: the engine build identity changes, as with every engine release. A game saved on
   the R1 engine answers `checkpoint_incompatible` after the R2 update; the apps already offer to
   abandon it.
5. **Native rebuild**: all three items change adapter sources, so R2 needs a fresh native engine on
   both platforms.
