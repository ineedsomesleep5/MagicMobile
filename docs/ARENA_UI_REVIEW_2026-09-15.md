# Arena-inspired native UI review — 2026-09-15

## Scope and design decisions

Selected checkout: `MagicMobile-runtime-hardening`, branch `codex/native-runtime-hardening`.
This is the existing SwiftUI product and XMage engine, not a replacement rules engine or a web/Three.js port.

- Compact near-square battlefield faces retain current power/toughness, counters, tapped state and engine-supplied ability indicators. Full printed cards remain available through inspection. Row density targets at least five cards before scrolling at normal phone widths, with a 44-point minimum card width.
- Ordinary priority no longer reserves a central decision banner; turn/priority information stays in the HUD and action dock. Targeting, combat and payment guidance remains. Crowded permanent lanes can use two rows only when the measured height fits two 44-point targets plus spacing; narrow lanes scroll by actual content width. Land lanes stay independent.
- The hand rests partly tucked, with printed mana symbols above cards, a 44-point expand/tuck control, horizontal scrolling, long-press inspection, and upward dragging to play. Printed costs are not an affordability calculation.
- The visible hand slider stays slim but has a 44-point touch target, sharing a bottom row with the expand/tuck button. Thumb dragging and track taps move the actual hand scroll offset continuously; swipes update the same inset-aware progress. Gesture-lifetime state resets interrupted scrubs. Accessibility adjustments move by ten percent. A separate 23-card development fixture exercises both ends of an oversized hand.
- The bottom enclosing panel is replaced by a floating life badge, circular secondary controls, and a primary action on the right. Consequential actions retain short labels. Required payment/choice controls are never silently skipped.
- Landscape uses a readable right-side stack peek; the complete stack inspector remains reachable. Large card-choice browsers are reserved for real selection/search prompts, not routine priority.
- Combat arrows use measured card coordinates and lane ownership; clipped combat cards have individually accessible edge-menu entries.
- Deck building uses collection and editable deck columns in landscape and separate tabs in portrait. Existing import validation, draft persistence and play-time legality remain authoritative. EDHREC remains the existing explicit external recommendations handoff, not an invented automated API integration.

### Rules and privacy boundaries

XMage's offered cast action is not a guarantee that the entire cost can be paid. A real Tribunal regression confirms that the engine can offer casting before the final cost can be satisfied. Such cards remain draggable but use a neutral offered-action indicator rather than a false affordable purple glow. No client-side mana-count guess is substituted for engine decisions.

The native projection now identifies actual mana abilities and current menace metadata. Real JVM regressions cover Sol Ring, Signets, Jaspera Sentinel's extra creature cost, the actual convoke special-action sequence, six-card sacrifice selection/deselection/cancellation, and granted/removed menace. These checks are separate from native iPhone execution.

Log inspection uses only the printed identity in an already-public log reference, never the object's current potentially hidden zone. Rules markup is decoded to bounded inert native text. Inspection requests larger artwork, keeps offline fallback images, preserves Scryfall consent, and bounds bytes, decoded pixels, redirects and cancellation.
