# Expected-match leave review

Run `npm ci --prefix supabase/tests --ignore-scripts` followed by `npm test --prefix supabase/tests`. The pinned PGlite package runs PostgreSQL in memory without Docker or a server. The harness reconstructs the five matchmaking tables, constraints/indexes, 28 function definitions, function ACLs and public read policies from `matchmaking-schema-metadata.json`, a read-only metadata snapshot of MagicMobile taken on 2026-09-20. It includes no production rows, keys or tokens. Only `auth.users`, `auth.uid()`, and Realtime side effects are minimal test substitutes; Realtime triggers and delivery are outside this test's scope.

The local migration and four rollback fixtures have passed in PGlite. `expected_match_leave.sql` checks invoker/definer ACLs, shared-lock coverage, missing UID, wrong match ID, repeat leave, waiting host election, and both new/legacy nonhost active leave ending every seat and transport. `exact_build_identity.sql` checks incompatible adapters cannot join/match, compatible iOS/Android identities succeed, and queue tenure resets only when identity changes. `waiting_seat_reuse.sql` checks replacements, departed-row retention, same-user rejoin, and active-seat uniqueness. `public_lobby_lifecycle.sql` executes the public status/create/join/both-ready/start/nonhost-leave/status sequence entirely under the authenticated role, including transport retirement. Execution found and fixed the existing ambiguous `ON CONFLICT (match_id,user_id)` in the join function by naming its primary-key constraint. No fixture or migration has been run against the live project.

Seat uniqueness changes from unconditional `(match_id,seat)` to a unique partial index for `left_at IS NULL`. The `(match_id,user_id)` primary key stays unchanged. Departed participants retain their rows; rejoining the same participant updates that person's existing row as before. This retains the current membership-history model rather than adding a separate event history. Read-only dependency inspection found only the old constraint's internal index, with no dependent foreign keys. The migration drops the constraint without CASCADE so new unexpected dependencies fail safely.

Before deployment, also run a two-session concurrency test on that disposable database:

1. Session A: begin; take `pg_advisory_xact_lock(1936028278, 1)`; invoke expected-ID leave as a fixture authenticated user; keep the transaction open.
2. Session B: as the same user, call create/join/enqueue. Confirm it waits before any membership change, then succeeds or returns the current match after A commits. Repeat in reverse order: A creates or joins a new lobby; B sends the old lobby ID and must fail without leaving the new lobby.
3. Repeat with enqueue selecting this user as another queued participant, and with a direct call to the private implementation. These paths must take the same lock.
4. Repeat legacy parameterless leave and direct private leave to confirm neither bypasses whole-match retirement.

The global transaction lock deliberately serializes this small MVP's matchmaking writes and status cleanup. This is a conservative concurrency contract, not a high-throughput matchmaker. Existing function ACLs remain unchanged; authenticated private EXECUTE is needed by the existing public invoker wrappers. No API role should have direct table DML or another privileged membership-mutation function that bypasses these locks. Read-only live ACL inspection confirmed authenticated has SELECT-only access to matches/players and no quick_queue DML. Inspect grants/functions again before applying; this test snapshot is not a deployment baseline migration.

PGlite is single-process: successful SQL execution and lock-source coverage do **not** prove concurrent transaction scheduling. The two-session checks above remain a release gate for a full PostgreSQL test database.
